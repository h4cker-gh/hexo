# v0.1.2 Release Notes

**Date:** 2026-11-19
**Type:** Minor feature release

## Summary

Completed the command system wiring: ping replies are sent back to WhatsApp, all 5 commands are registered, Memory service is wired in DI, and the help command accesses the registry via `context.variables`.

## Changes

### New Features
- **Command reply pipeline:** `ping` command (and all others) now send replies back via `WhatsAppAdapter.sendText()` — the `onContext` callback captures `CommandResult` from `execute()` and dispatches text/error responses.
- **Memory service:** `MemoryServiceImpl` registered in the DI container as a singleton, accessible via `context.variables.get('memory')`.
- **Full command registry:** All 5 commands registered at init — `ping`, `help`, `profile`, `tagall`, `chatinfo`.

### Improvements
- **Help command:** Refactored to access the registry via `context.variables` instead of a 3rd handler parameter, avoiding circular DI concerns.
- **Adapter:** Added `setOnContext()` setter to wire the message-processing callback after construction; logs success on `sendMessage()`.
- **Context builder:** `onContext` callback now populates `context.variables` with registry accessors (`getCommands`, `getMetadata`) and the `memory` service instance.

### Bug Fixes
- Fixed `execute()` call to pass 3 args (`name`, `context`, `logger`) per `CommandRegistry` signature.
- Fixed `sendText()` calls to use `content` field (not `text`) per `TextMessageParams` interface.
- Removed unused imports (`isGroupJid` from chatinfo.ts, `CommandDefinition` from container.ts).
- Fixed string indexing in chatinfo flag parsing to avoid `string[index]` possibly-undefined TypeScript error.
- Removed dead code from Memory service (`DEFAULT_TTL_MS`, `getLocalKey`).

### Testing
- TypeScript compiles with **0 errors**.
- All **81 tests** pass across **11 test files**.
